### 1. What the misconfiguration is
Checkov flagged three distinct issues across your DynamoDB tables:
- **Point-in-Time Recovery (PITR) is disabled**: None of the four tables (`cmk`, `default`, `encrypted_false`, `encrypted_no_cmk`) have the `point_in_time_recovery` block configured.
- **Missing Customer Managed Key (CMK)**: The `default` table lacks a `server_side_encryption` block entirely; `encrypted_false` explicitly disables it; and `encrypted_no_cmk` enables encryption but omits the `kms_key_arn`, causing it to fall back to an AWS-managed key.
- **Missing Auto Scaling**: All four tables use `billing_mode = "PROVISIONED"` but lack associated `aws_appautoscaling_target` and `aws_appautoscaling_policy` resources to dynamically adjust capacity.

### 2. Why it matters (security risk / blast radius)
- **Data loss**: Without PITR, you cannot recover the table to its state prior to an accidental deletion or destructive write. Any logical corruption or bad script execution results in permanent data loss.
- **Lack of cryptographic control**: Using an AWS-managed key instead of a CMK means you cannot control key access policies, rotation schedules, or revoke access to the encryption key independently of the AWS service. If compliance requires strict key isolation, AWS-managed keys will fail the requirement.
- **Availability/Throttling**: Without auto-scaling (or on-demand capacity), fixed provisioned throughput can lead to request throttling during traffic spikes, denying legitimate access to the application, or result in over-provisioning and wasted spend.

### 3. How to fix it safely
Apply the following changes to your Terraform configuration:

**Enable Point-in-Time Recovery** on all tables by adding:
```hcl
  point_in_time_recovery {
    enabled = true
  }
```

**Enforce CMK Encryption** by adding or updating the `server_side_encryption` block on `default`, `encrypted_false`, and `encrypted_no_cmk` to reference your KMS key (using the same `kms_key_arn` as the `cmk` table or a data source reference):
```hcl
  server_side_encryption {
    enabled     = true
    kms_key_arn = "arn:aws:kms:us-west-2:123456789012:key/1234abcd-12ab-34cd-56ef-1234567890ab"
  }
```

**Resolve Auto Scaling** using one of two approaches:
1. **Switch to On-Demand capacity** (simplest if traffic is unpredictable): Remove `read_capacity` and `write_capacity`, and set `billing_mode = "PAY_PER_REQUEST"`. This inherently removes the need for auto-scaling policies.
2. **Add Auto Scaling resources** (if staying PROVISIONED): Define `aws_appautoscaling_target` and `aws_appautoscaling_policy` resources for both read and write capacity units for each table to adjust capacity between defined minimum and maximum bounds.
