The scanner flagged two IAM policy documents in your Terraform file. Even though one is named `pass`, it still fails certain checks. Below I explain every finding, why it’s a risk, and how to fix it.

## 1. `data "aws_iam_policy_document" "pass"` (lines 42–56)

**Policy content:**
```hcl
statement {
  effect = "Allow"
  actions = [
    "lambda:CreateFunction",
    "lambda:CreateEventSourceMapping",
    "dynamodb:CreateTable",
  ]
  resources = ["*"]
}
```

### Findings on this policy

| Check ID | Title | Why it’s flagged |
|----------|-------|------------------|
| **CKV_AWS_111** | Ensure IAM policies does not allow write access without constraints | The actions `Create*` are write operations. The policy allows them on **all resources** (`"*"`) with no conditions (e.g., no `condition` block, no specific resource ARNs). This grants unrestricted write access. |
| **CKV_AWS_356** | Ensure no IAM policies documents allow `"*"` as a statement's resource for restrictable actions | The actions listed are “restrictable” (you can scope them to specific resources). Using `"*"` as the resource violates the principle of least privilege. |

### How to fix

- **Replace `"*"` with specific resource ARNs** for the Lambda functions, event source mappings, and DynamoDB tables that actually need these permissions.
- **Add conditions** if you must allow a broader set of resources (e.g., `StringLike` on resource ARN, or `aws:RequestedRegion`).
- If the policy is meant to be a “pass” (i.e., compliant), rename it to avoid confusion.

**Example remediation:**
```hcl
data "aws_iam_policy_document" "pass" {
  statement {
    effect = "Allow"
    actions = [
      "lambda:CreateFunction",
      "lambda:CreateEventSourceMapping",
    ]
    resources = [
      "arn:aws:lambda:us-east-1:123456789012:function:my-function-*",
    ]
  }
  statement {
    effect = "Allow"
    actions = [
      "dynamodb:CreateTable",
    ]
    resources = [
      "arn:aws:dynamodb:us-east-1:123456789012:table/my-table-*",
    ]
  }
}
```
If you need to allow creation of any table/function but only in a specific region, add a condition:
```hcl
condition {
  test     = "StringEquals"
  variable = "aws:RequestedRegion"
  values   = ["us-east-1"]
}
```

## 2. `data "aws_iam_policy_document" "fail"` (lines 60–73)

**Policy content:**
```hcl
statement {
  effect = "Allow"
  actions = [
    "s3:GetObject",
    "iam:CreateAccessKey"
  ]
  resources = ["*"]
}
```

### Findings on this policy

| Check ID | Title | Why it’s flagged |
|----------|-------|------------------|
| **CKV_AWS_108** | Ensure IAM policies does not allow data exfiltration | `s3:GetObject` allows reading objects from S3. With `"*"` as the resource, an identity with this policy can read **any** object in **any** bucket, enabling mass data exfiltration. |
| **CKV_AWS_107** | Ensure IAM policies does not allow credentials exposure | `iam:CreateAccessKey` allows creating long-term access keys for IAM users. This can expose credentials if misused. |
| **CKV_AWS_356** | Ensure no IAM policies documents allow `"*"` as a statement's resource for restrictable actions | Both `s3:GetObject` and `iam:CreateAccessKey` are restrictable actions, yet the resource is `"*"`. |
| **CKV_AWS_109** | Ensure IAM policies does not allow permissions management / resource exposure without constraints | `iam:CreateAccessKey` is a permissions management action (it creates credentials that grant access). Allowing it on `"*"` without constraints is dangerous. |
| **CKV_AWS_110** | Ensure IAM policies does not allow privilege escalation | `iam:CreateAccessKey` can be used for privilege escalation (e.g., creating an access key for a more privileged user). |

### How to fix

- **Remove `iam:CreateAccessKey`** unless absolutely necessary. If it is required, restrict the `resource` to specific IAM user ARNs and add conditions (e.g., MFA, source IP).
- **Restrict `s3:GetObject`** to specific bucket/object ARNs. Use path prefixes or tags to limit scope. Add conditions like `s3:ExistingObjectTag` or `aws:SourceVpc` if applicable.
- **Never use `"*"` as resource** for these actions.

**Example remediation (least privilege):**
```hcl
data "aws_iam_policy_document" "fail" {
  statement {
    effect = "Allow"
    actions = [
      "s3:GetObject",
    ]
    resources = [
      "arn:aws:s3:::my-app-bucket/uploads/*",
    ]
    condition {
      test     = "StringEquals"
      variable = "aws:SourceVpc"
      values   = ["vpc-0abc123def456"]
    }
  }
  # Only if absolutely needed:
  statement {
    effect = "Allow"
    actions = [
      "iam:CreateAccessKey",
    ]
    resources = [
      "arn:aws:iam::123456789012:user/${aws:username}",
    ]
    condition {
      test     = "Bool"
      variable = "aws:MultiFactorAuthPresent"
      values   = ["true"]
    }
  }
}
```

If `iam:CreateAccessKey` is not required, simply remove it from the policy.
