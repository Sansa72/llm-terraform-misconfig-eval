The security scanner has identified several missing configurations on your S3 bucket resource. Each finding represents a security best practice that should be implemented to protect data, ensure compliance, and improve operational resilience. Below I explain each issue, why it matters, and how to fix it in Terraform.

### 1. CKV2_AWS_61 – Lifecycle Configuration
**Problem:** The bucket has no lifecycle rules.  
**Why it matters:** Lifecycle policies help manage storage costs and data retention by automatically transitioning objects to cheaper storage classes or expiring them after a defined period. Without them, data may accumulate indefinitely, increasing cost and risk.  
**Fix:** Add an `aws_s3_bucket_lifecycle_configuration` resource. Example:
```hcl
resource "aws_s3_bucket_lifecycle_configuration" "bucket_lifecycle" {
  bucket = aws_s3_bucket.bucket.id

  rule {
    id     = "expire-old-objects"
    status = "Enabled"

    expiration {
      days = 365
    }
  }
}
```
Adjust the rule to match your retention requirements.

### 2. CKV_AWS_18 – Access Logging
**Problem:** Server access logging is not enabled.  
**Why it matters:** Access logs provide detailed records of requests made to the bucket, essential for security audits, anomaly detection, and forensic investigations.  
**Fix:** Create a target bucket for logs (or use an existing one) and attach a logging configuration. Example:
```hcl
resource "aws_s3_bucket" "log_bucket" {
  bucket = "module-bucket-logs"
}

resource "aws_s3_bucket_logging" "bucket_logging" {
  bucket = aws_s3_bucket.bucket.id

  target_bucket = aws_s3_bucket.log_bucket.id
  target_prefix = "log/"
}
```
Ensure the log bucket has appropriate permissions (ACL or bucket policy) to allow S3 to write logs.

---

### 3. CKV2_AWS_62 – Event Notifications
**Problem:** No event notifications are configured.  
**Why it matters:** Event notifications enable real-time reactions to object changes (e.g., triggering a Lambda function, sending to SQS/SNS). This is critical for security automation, data processing pipelines, and monitoring.  
**Fix:** Add an `aws_s3_bucket_notification` resource. Example for sending events to an SNS topic:
```hcl
resource "aws_s3_bucket_notification" "bucket_notification" {
  bucket = aws_s3_bucket.bucket.id

  topic {
    topic_arn     = aws_sns_topic.bucket_events.arn
    events        = ["s3:ObjectCreated:*"]
    filter_prefix = "data/"
  }
}
```
You’ll need to create the SNS topic and appropriate permissions.

### 4. CKV2_AWS_6 – Public Access Block
**Problem:** The bucket does not have a public access block configuration.  
**Why it matters:** Without explicit block settings, the bucket could accidentally be made public via bucket policies or ACLs, leading to data exposure.  
**Fix:** Add an `aws_s3_bucket_public_access_block` resource to enforce blocking of all public access:
```hcl
resource "aws_s3_bucket_public_access_block" "bucket_public_access" {
  bucket = aws_s3_bucket.bucket.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

### 5. CKV_AWS_145 – Default Encryption with KMS
**Problem:** The bucket is not configured to use KMS-managed encryption by default.  
**Why it matters:** Default encryption ensures all objects are encrypted at rest. Using AWS KMS (rather than SSE-S3) gives you control over key rotation, access policies, and audit trails.  
**Fix:** Add an `aws_s3_bucket_server_side_encryption_configuration` resource with KMS:
```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "bucket_encryption" {
  bucket = aws_s3_bucket.bucket.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = aws_kms_key.s3_key.arn  # or use an existing KMS key ARN
    }
  }
}
```
You’ll need to create a KMS key or reference an existing one.

### 6. CKV_AWS_144 – Cross-Region Replication
**Problem:** Cross-region replication (CRR) is not enabled.  
**Why it matters:** CRR automatically replicates objects to a bucket in another AWS region, providing geographic redundancy for disaster recovery and compliance.  
**Fix:** Set up replication configuration. This requires:
- A destination bucket in a different region.
- An IAM role with permissions to replicate.
- A replication configuration resource.

Example (simplified):
```hcl
# Destination bucket in another region
resource "aws_s3_bucket" "replica" {
  provider = aws.replica_region
  bucket   = "module-bucket-replica"
}

# IAM role for replication
resource "aws_iam_role" "replication" {
  name = "s3-replication-role"
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Principal = { Service = "s3.amazonaws.com" }
      Action = "sts:AssumeRole"
    }]
  })
}

# Replication configuration
resource "aws_s3_bucket_replication_configuration" "bucket_replication" {
  role   = aws_iam_role.replication.arn
  bucket = aws_s3_bucket.bucket.id

  rule {
    id     = "replicate-everything"
    status = "Enabled"

    destination {
      bucket        = aws_s3_bucket.replica.arn
      storage_class = "STANDARD"
    }
  }
}
```
Note: Both source and destination buckets must have versioning enabled.

### 7. CKV_AWS_21 – Versioning
**Problem:** Versioning is not enabled.  
**Why it matters:** Versioning protects against accidental overwrites and deletions by keeping multiple variants of an object. It is a prerequisite for replication and many backup strategies.  
**Fix:** Add an `aws_s3_bucket_versioning` resource:
```hcl
resource "aws_s3_bucket_versioning" "bucket_versioning" {
  bucket = aws_s3_bucket.bucket.id
  versioning_configuration {
    status = "Enabled"
  }
}
```
