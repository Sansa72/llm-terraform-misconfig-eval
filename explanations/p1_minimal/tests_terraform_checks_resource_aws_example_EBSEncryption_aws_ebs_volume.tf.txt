The scanner flagged two distinct but related issues across your EBS volumes:

1. **CKV_AWS_3** – “Ensure all data stored in the EBS is securely encrypted”  
   This check requires that the volume be encrypted at all (using either the default AWS-managed key or a customer-managed key).

2. **CKV_AWS_189** – “Ensure EBS Volume is encrypted by KMS using a customer managed Key (CMK)”  
   This check goes further: encryption alone is not enough; the key must be a **customer-managed KMS key** (CMK), not the default `aws/ebs` AWS-managed key.

Here’s how each resource fails:

| Resource | `encrypted` | `kms_key_id` | CKV_AWS_3 (any encryption) | CKV_AWS_189 (CMK) |
|----------|-------------|--------------|----------------------------|-------------------|
| `aws_ebs_volume.enabled` | `true` | *not set* | ✅ Pass | ❌ Fail – uses default AWS-managed key |
| `aws_ebs_volume.default` | *not set* (defaults to `false`) | *not set* | ❌ Fail – not encrypted | ❌ Fail – not encrypted |
| `aws_ebs_volume.disabled` | `false` | *not set* | ❌ Fail – explicitly disabled | ❌ Fail – explicitly disabled |

**What you need to do**  
- For all three volumes, set `encrypted = true`.  
- Provide a `kms_key_id` that points to a **customer-managed KMS key** (CMK). You can either create a new key in the same Terraform configuration or reference an existing one by ARN.

**Example fix** (creating a new CMK and using it for all volumes):

```hcl
# Create a customer-managed KMS key for EBS encryption
resource "aws_kms_key" "ebs" {
  description             = "Customer-managed key for EBS volume encryption"
  deletion_window_in_days = 7
  enable_key_rotation     = true
}

resource "aws_kms_alias" "ebs" {
  name          = "alias/ebs-cmk"
  target_key_id = aws_kms_key.ebs.key_id
}

# Volume that was already encrypted but with the default key
resource "aws_ebs_volume" "enabled" {
  availability_zone = "us-west-2a"
  size              = 20

  encrypted  = true
  kms_key_id = aws_kms_key.ebs.arn   # now uses CMK
}

# Volume that had no encryption setting
resource "aws_ebs_volume" "default" {
  availability_zone = "us-west-2a"
  size              = 20

  encrypted  = true
  kms_key_id = aws_kms_key.ebs.arn
}

# Volume that had encryption explicitly disabled
resource "aws_ebs_volume" "disabled" {
  availability_zone = "us-west-2a"
  size              = 20

  encrypted  = true
  kms_key_id = aws_kms_key.ebs.arn
}
```

**Key points to remember**  
- The `kms_key_id` can be a key ARN, key ID, alias ARN, or alias name. Using the key’s ARN (as above) is unambiguous.  
- If you already have a CMK in your account, you can reference it directly: `kms_key_id = "arn:aws:kms:us-west-2:123456789012:key/abcd-1234..."`.  
- After applying, the volumes will be encrypted with your CMK, satisfying both `CKV_AWS_3` and `CKV_AWS_189`.
