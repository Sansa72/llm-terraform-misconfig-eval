**Check: CKV_AWS_184 – Resource: `aws_efs_file_system.fail` (lines 6–8)**  
**What is wrong:** The file system is configured with `encrypted = true` but does not specify a `kms_key_id`, so it will use the default AWS-managed key for EFS encryption instead of a customer managed key (CMK).  
**Why it matters:** Using a customer managed KMS key gives you control over key rotation, access policies, and audit trails. Relying on the AWS-managed key limits your ability to enforce granular security controls and meet compliance requirements that mandate CMK usage.  
**Change needed:** Add a `kms_key_id` argument that references the ARN of an existing customer managed KMS key. The file already contains a suitable key (`aws_kms_key.test.arn`) used by the `aws_efs_file_system.pass` resource; you can reuse that same key or reference another CMK you manage. The attribute should be placed alongside `encrypted = true` inside the `aws_efs_file_system.fail` block. No other modifications are required.
