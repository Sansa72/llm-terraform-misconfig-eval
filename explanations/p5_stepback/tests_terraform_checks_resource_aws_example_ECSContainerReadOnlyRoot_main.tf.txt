- **CKV_AWS_334 – Non-privileged containers**  
  *Principle*: Running a container in privileged mode gives it all Linux capabilities and effectively removes the isolation between the container and the host. A compromised privileged container can easily escape to the host, leading to full host takeover.  
  *Violation*: The second container definition (`"name": "second"`) includes `"privilege": true`, which runs the container with elevated privileges.  
  *Fix*: Remove the `"privilege": true` line (or set it to `false`). The container will then run with the default unprivileged mode.

- **CKV_AWS_335 – Do not share the host’s process namespace**  
  *Principle*: Sharing the host’s PID namespace (`pidMode: host`) allows a container to see and interact with all processes on the host, including those of other containers. This breaks process isolation and can be exploited for information disclosure or privilege escalation.  
  *Violation*: The second container definition in `fail2` includes `"pidMode": "host"`, which would cause the task to use the host’s process namespace.  
  *Fix*: Remove the `"pidMode": "host"` line from the container definition. If you need to set the task’s PID mode, use the task-level `pid_mode` argument in the `aws_ecs_task_definition` resource (not inside the container definition), and only set it to `"task"` (the default) to maintain process isolation.
