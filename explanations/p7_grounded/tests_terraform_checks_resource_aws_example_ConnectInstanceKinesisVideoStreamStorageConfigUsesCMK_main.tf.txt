### Finding 1: CKV_AWS_269 on `aws_connect_instance_storage_config.fail` (lines 20‑35)

**Check description:** Ensure Connect Instance Kinesis Video Stream Storage Config uses CMK.

**What the code shows:**  
The `fail` resource defines a `kinesis_video_stream_config` block with an `encryption_config` that sets `encryption_type = "KMS"` but **omits the `key_id` argument** (lines 30‑33).  
Without `key_id`, the Kinesis Video Stream will be encrypted with an AWS-managed key, not a Customer Managed Key (CMK). The check requires a CMK.

**Evidence in the file:**  
- Lines 30‑33:  
  ```hcl
  encryption_config {
    encryption_type = "KMS"
  }
  ```
  No `key_id` is specified.

**Contrast with the “pass” resource (lines 1‑17):**  
The same block in the `pass` resource includes `key_id = aws_kms_key.test.arn` (line 13), which satisfies the CMK requirement. The scanner did **not** raise CKV_AWS_269 against the `pass` resource, confirming that the missing `key_id` is the trigger.

**Action:** Add a `key_id` argument pointing to a valid KMS key ARN inside the `encryption_config` block of the `fail` resource.
