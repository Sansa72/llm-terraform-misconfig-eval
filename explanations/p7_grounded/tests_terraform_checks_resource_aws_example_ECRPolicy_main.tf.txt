```terraform
}
```

**Finding:**
- **CKV_AWS_32** – Ensure ECR policy is not set to public

**Evidence:**  
The policy uses `"Principal": "*"` (line 141) and attempts to restrict access with a condition on `aws:username`. The scanner considers this policy public because `aws:username` is not a secure, immutable attribute for access control (any IAM user can set their own username). The presence of `Principal: *` without a valid, restrictive condition triggers the public-policy check. The finding points to the entire policy resource (lines 131–165).

### Summary of required fixes

For every `aws_ecr_repository` resource that is flagged, you need to add:

- `image_scanning_configuration { scan_on_push = true }` (addresses CKV_AWS_163)
- `encryption_configuration { encryption_type = "KMS" }` (or specify a KMS key; addresses CKV_AWS_136)
- `image_tag_mutability = "IMMUTABLE"` (addresses CKV_AWS_51)

For the two `aws_ecr_repository_policy` resources flagged with CKV_AWS_32, you must ensure the policy is not public. This means either:
- Replace `"Principal": "*"` with specific AWS principals (accounts, IAM users/roles), or
- Keep `"Principal": "*"` but add a condition that uses a secure, AWS‑managed attribute (e.g., `aws:PrincipalOrgID` with `StringEquals` or `ForAnyValue:StringEquals`), not `aws:username`.

The file already contains examples of compliant policies (e.g., `pass`, `pass_conditional`, `cond_any_pass`, `cond_equals_pass`) that you can use as a reference.
