### CKV_AWS_323 – “Ensure ElastiCache clusters do not use the default subnet group”

**Flagged on:**
- `aws_elasticache_cluster.pass` (lines 3–11)
- `aws_elasticache_cluster.pass2` (lines 13–19)
- `aws_elasticache_cluster.fail` (lines 21–29)
- `aws_elasticache_cluster.memcached` (lines 33–39)

**What the check requires:**  
The cluster must be assigned a custom subnet group. If no `subnet_group_name` is specified, the cluster uses the **default subnet group** for the VPC, which is considered a security misconfiguration.

**Evidence in the file:**  
None of the four resource blocks include a `subnet_group_name` argument. For example, the `pass` resource (lines 3–11) defines `cluster_id`, `engine`, `node_type`, etc., but no subnet group. The same omission exists in the other three blocks. Because the attribute is absent, each cluster will fall back to the default subnet group, triggering the check.

### CKV_AWS_134 – “Ensure that Amazon ElastiCache Redis clusters have automatic backup turned on”

**Flagged on:**
- `aws_elasticache_cluster.pass2` (lines 13–19)
- `aws_elasticache_cluster.fail` (lines 21–29)

**What the check requires:**  
For Redis clusters, automatic backups must be enabled. In Terraform, this is controlled by `snapshot_retention_limit` – a value greater than 0 enables backups; 0 or omitting the argument disables them.

**Evidence in the file:**
- **`pass2` (lines 13–19):** The block does **not** include `snapshot_retention_limit`. The default value is 0, meaning automatic backups are disabled.  
- **`fail` (lines 21–29):** Line 29 explicitly sets `snapshot_retention_limit = 0`, which also disables backups.  

The `pass` resource (lines 3–11) is **not** flagged because it sets `snapshot_retention_limit = 5` (line 10), satisfying the check.
