## Remediation Briefing

Below are the failing checks in the order reported by the scanner. For each, the exact resource, triggering lines, a one‑line explanation of the problem, and the required change are given. Only evidence present in the file and the finding is used.

---

### 1. CKV_AWS_150 on `aws_lb.pass` (lines 3‑10)
**What is wrong:** The load balancer does not have deletion protection enabled.  
**Why it matters:** Without deletion protection, the load balancer can be accidentally deleted, causing an outage.  
**Change needed:** Add the attribute `enable_deletion_protection = true` inside the `aws_lb` resource block.

---

### 2. CKV_AWS_91 on `aws_lb.pass` (lines 3‑10)
**What is wrong:** Access logging is not configured for this Application Load Balancer.  
**Why it matters:** Missing access logs removes visibility into traffic patterns and potential security events.  
**Change needed:** Add an `access_logs` block to the resource, specifying at minimum a valid S3 bucket name (e.g., `bucket = "my-log-bucket"`). The block itself enables logging.

### 5. CKV_AWS_127 on `aws_elb.pass` (lines 19‑61)
**What is wrong:** The HTTPS listener (line 43) uses an IAM server certificate (`arn:aws:iam::...`) instead of an AWS Certificate Manager (ACM) certificate.  
**Why it matters:** IAM certificates are legacy; ACM provides automatic renewal and better integration.  
**Change needed:** Replace the `ssl_certificate_id` value with the ARN of an ACM certificate in the same region (e.g., `arn:aws:acm:us-west-2:123456789012:certificate/...`).

### 7. CKV_AWS_328 on `aws_elb.fail` (lines 64‑106)
**What is wrong:** The `desync_mitigation_mode` is set to `"monitor"` (line 97), which is not the required defensive or strictest mode.  
**Why it matters:** The check requires a stronger mitigation mode to protect against HTTP desync attacks.  
**Change needed:** Change the value of `desync_mitigation_mode` to `"defensive"` or `"strictest"`.  
*Note:* The `aws_elb` resource type (Classic Load Balancer) does not natively support this attribute. If this is truly a Classic ELB, the attribute should be removed and the resource migrated to an Application Load Balancer (`aws_lb` with `load_balancer_type = "application"`) to properly satisfy the check.
