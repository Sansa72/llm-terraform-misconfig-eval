## Remediation Briefing

Below are the failing checks in the order reported by the scanner. For each, the exact trigger location, the problem, and the required change are described.

### 1. CKV_AWS_34 on `aws_cloudfront_distribution.fail` (lines 1‑104)
- **Trigger:** `viewer_protocol_policy = "allow-all"` in the `default_cache_behavior` block at **line 37**.
- **What is wrong:** The default cache behaviour allows unencrypted HTTP connections, which can expose traffic to interception.
- **Change needed:** Set `viewer_protocol_policy` to `"redirect-to-https"` (or `"https-only"`) inside the `default_cache_behavior` block so that all requests are served over HTTPS.

### 2. CKV_AWS_174 on `aws_cloudfront_distribution.fail` (lines 1‑104)
- **Trigger:** The `viewer_certificate` block at **lines 101‑103** uses `cloudfront_default_certificate = true` and does not specify a `minimum_protocol_version`. The default minimum protocol version is TLSv1, which is weaker than TLSv1.2.
- **What is wrong:** The distribution’s viewer certificate does not enforce TLSv1.2 or higher.
- **Change needed:** Add `minimum_protocol_version = "TLSv1.2_2018"` (or a later TLSv1.2 policy) inside the `viewer_certificate` block. If you continue using the default CloudFront certificate, this attribute is still valid.

### 3. CKV_AWS_68 on `aws_cloudfront_distribution.fail` (lines 1‑104)
- **Trigger:** The resource does not contain a `web_acl_id` argument anywhere in the block (lines 1‑104).
- **What is wrong:** No WAF web ACL is associated with the distribution, leaving it without AWS WAF protection.
- **Change needed:** Add `web_acl_id = aws_wafv2_web_acl.<name>.arn` (or the ARN of an existing WAF Web ACL) to the distribution resource.

### 4. CKV_AWS_310 on `aws_cloudfront_distribution.fail` (lines 1‑104)
- **Trigger:** Only one `origin` block is present (lines 2‑9). There is no second origin and no `origin_group` block.
- **What is wrong:** The distribution has no origin failover configuration; a single origin is a single point of failure.
- **Change needed:** Add a second `origin` block and an `origin_group` block that references both origins, with failover criteria, so that CloudFront can fall back to the secondary origin if the primary fails.
