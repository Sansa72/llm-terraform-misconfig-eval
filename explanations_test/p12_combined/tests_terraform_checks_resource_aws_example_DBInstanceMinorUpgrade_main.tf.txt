## Remediation Briefing

Below are the failing checks in the order reported by the scanner. For each, the resource, the exact lines that trigger the issue, a one-line explanation of the problem, and the required change are given.

---

### 1. CKV_AWS_354 on `aws_rds_cluster_instance.fail` (lines 1–7)
**Trigger:** The attribute `performance_insights_kms_key_id` is not set, and `performance_insights_enabled` is `false` (line 3).  
**What is wrong:** Performance Insights is not encrypted with a customer-managed KMS key.  
**Why it matters:** Without a CMK, Performance Insights data is encrypted with an AWS-managed key, reducing control over key lifecycle and access.  
**Change needed:** Set `performance_insights_enabled = true` and provide a valid KMS CMK ARN in `performance_insights_kms_key_id`.

### 2. CKV_AWS_353 on `aws_rds_cluster_instance.fail` (lines 1–7)
**Trigger:** `performance_insights_enabled = false` (line 3).  
**What is wrong:** Performance Insights is disabled.  
**Why it matters:** Without Performance Insights, database performance monitoring and troubleshooting are impaired.  
**Change needed:** Set `performance_insights_enabled = true`.

### 3. CKV_AWS_226 on `aws_rds_cluster_instance.fail` (lines 1–7)
**Trigger:** `auto_minor_version_upgrade = false` (line 5).  
**What is wrong:** Automatic minor version upgrades are turned off.  
**Why it matters:** Missing minor upgrades can leave the instance vulnerable to known security issues.  
**Change needed:** Set `auto_minor_version_upgrade = true`.

### 4. CKV_AWS_17 on `aws_rds_cluster_instance.fail` (lines 1–7)
**Trigger:** `publicly_accessible = true` (line 4).  
**What is wrong:** The database instance is publicly accessible.  
**Why it matters:** Public accessibility exposes the database to the internet, increasing the attack surface.  
**Change needed:** Set `publicly_accessible = false`.

### 5. CKV_AWS_118 on `aws_rds_cluster_instance.fail` (lines 1–7)
**Trigger:** No `monitoring_interval` or `monitoring_role_arn` is present.  
**What is wrong:** Enhanced monitoring is not enabled.  
**Why it matters:** Without enhanced monitoring, you lose granular OS-level metrics needed for performance and security analysis.  
**Change needed:** Set `monitoring_interval` to a value greater than 0 (e.g., 60) and provide a valid `monitoring_role_arn` for the IAM role that permits enhanced monitoring.
