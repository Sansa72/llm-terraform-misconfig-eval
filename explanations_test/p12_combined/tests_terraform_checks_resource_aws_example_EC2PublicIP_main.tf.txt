**Remediation briefing for Terraform EC2 security findings**

Below each scanner finding is addressed in the order it appears. The file under review is the Terraform configuration provided. All line references are to that file.

---

### 1. CKV_AWS_79 on `aws_instance.default` (lines 5‑8)
- **Trigger**: The resource block at lines 5‑8 does not include a `metadata_options` block.
- **What is wrong**: The instance will allow IMDSv1 (Instance Metadata Service version 1), which is less resistant to certain types of credential theft than IMDSv2.
- **Change needed**: Add a `metadata_options` block inside the `aws_instance "default"` resource, setting `http_tokens = "required"`. This disables IMDSv1 and enforces IMDSv2.

### 2. CKV_AWS_126 on `aws_instance.default` (lines 5‑8)
- **Trigger**: The resource block at lines 5‑8 does not set `monitoring`.
- **What is wrong**: Detailed (1‑minute) CloudWatch monitoring is not enabled; the instance will only report basic 5‑minute metrics.
- **Change needed**: Add `monitoring = true` to the `aws_instance "default"` resource.

### 3. CKV_AWS_135 on `aws_instance.default` (lines 5‑8)
- **Trigger**: The resource block at lines 5‑8 does not set `ebs_optimized`.
- **What is wrong**: The instance is not explicitly flagged as EBS‑optimised, which may lead to suboptimal storage performance.
- **Change needed**: Add `ebs_optimized = true` to the `aws_instance "default"` resource.

### 4. CKV_AWS_8 on `aws_instance.default` (lines 5‑8)
- **Trigger**: The resource block at lines 5‑8 contains no `root_block_device` or `ebs_block_device` with encryption enabled.
- **What is wrong**: The root EBS volume (and any additional volumes) will be created without encryption, leaving data at rest unprotected.
- **Change needed**: Add a `root_block_device` block inside the resource, setting `encrypted = true`. If other EBS volumes are attached, add corresponding `ebs_block_device` blocks with `encrypted = true`.

### 5. CKV_AWS_79 on `aws_instance.private` (lines 10‑15)
- **Trigger**: The resource block at lines 10‑15 does not include a `metadata_options` block.
- **What is wrong**: IMDSv1 is allowed (same risk as #1).
- **Change needed**: Add `metadata_options { http_tokens = "required" }` to the `aws_instance "private"` resource.

### 6. CKV_AWS_126 on `aws_instance.private` (lines 10‑15)
