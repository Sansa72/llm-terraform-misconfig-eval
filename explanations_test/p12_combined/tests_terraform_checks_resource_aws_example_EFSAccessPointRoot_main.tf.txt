## Remediation Briefing

Below are the failing checks in the order reported, with the evidence from the file and the required change.

---

### 1. CKV_AWS_330 on `aws_efs_access_point.pass` (lines 1–6)

**What triggers it:**  
The resource block at lines 1–6 defines an access point with a `root_directory` but contains no `posix_user` block.

**What is wrong and why it matters:**  
The access point does not enforce a user identity, meaning file system operations are not tied to a specific POSIX user and group. This can allow unintended access or reliance on the client’s default identity.

**Change needed:**  
Add a `posix_user` block inside the `aws_efs_access_point.pass` resource, specifying a `uid` and `gid` (for example, `1000` and `1000`). This will enforce that all file accesses through this access point use that identity.
