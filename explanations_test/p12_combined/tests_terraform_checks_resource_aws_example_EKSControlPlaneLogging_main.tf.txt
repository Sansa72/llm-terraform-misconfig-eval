### Finding 1
- **Check ID:** CKV_AWS_39  
- **Resource:** `aws_eks_cluster.fully_enabled` (lines 3–14)  
- **Exact trigger lines:** The entire resource block (lines 3–14) lacks a `vpc_config` block.  
- **What is wrong and why it matters:** The EKS cluster does not explicitly disable the public endpoint. By default, the Kubernetes API endpoint is publicly accessible, which increases the attack surface.  
- **Remediation:** Add a `vpc_config` block inside the resource and set `endpoint_public_access = false`. If private access is needed, also set `endpoint_private_access = true` and provide appropriate subnet IDs.

### Finding 2
- **Check ID:** CKV_AWS_58  
- **Resource:** `aws_eks_cluster.fully_enabled` (lines 3–14)  
- **Exact trigger lines:** The resource block (lines 3–14) contains no `encryption_config` block.  
- **What is wrong and why it matters:** The cluster does not have envelope encryption enabled for Kubernetes secrets. Without this, secrets stored in etcd are not encrypted at rest using a KMS key, which is a security best practice.  
- **Remediation:** Add an `encryption_config` block that references a KMS key ARN and specifies `resources = ["secrets"]`.
