Below is the remediation briefing for each failing check, in the order reported by the scanner. Every statement is grounded in the provided Terraform file and the scanner findings.

---

### 1. CKV_AWS_39 on `aws_eks_cluster.pass` (lines 1–15)
**What is wrong:** The `vpc_config` block does not set `endpoint_public_access` to `false`, so the cluster’s public endpoint remains enabled (the default is `true`).  
**Why it matters:** A publicly accessible Kubernetes API endpoint increases the attack surface and may violate security policies that require private-only access.  
**Remediation:** Add `endpoint_public_access = false` inside the existing `vpc_config` block.

### 2. CKV_AWS_58 on `aws_eks_cluster.pass` (lines 1–15)
**What is wrong:** The resource does not contain an `encryption_config` block referencing a KMS key, so envelope encryption of Kubernetes secrets is not enabled.  
**Why it matters:** Without secrets encryption, sensitive data stored in etcd (such as Secrets) is not encrypted at the application level, increasing the risk of exposure if the underlying storage is compromised.  
**Remediation:** Add an `encryption_config` block that specifies a KMS key ARN and the `resources = ["secrets"]` list.

### 3. CKV_AWS_38 on `aws_eks_cluster.pass` (lines 1–15)
**What is wrong:** The `vpc_config` block does not include a `public_access_cidrs` argument, so the default `["0.0.0.0/0"]` is applied, allowing access to the public endpoint from any IP address.  
**Why it matters:** Unrestricted CIDR access to the API server makes the cluster reachable from anywhere on the internet, significantly increasing the risk of unauthorised access.  
**Remediation:** Add `public_access_cidrs` inside `vpc_config` and set it to a restricted list of trusted CIDR blocks (e.g., your corporate egress IPs).

### 4. CKV_AWS_37 on `aws_eks_cluster.pass` (lines 1–15)
**What is wrong:** The resource does not specify the `enabled_cluster_log_types` argument, so control plane logging is not enabled for any log type.  
**Why it matters:** Without control plane logs (API, audit, authenticator, controller manager, scheduler), it is difficult to audit cluster activity, detect anomalies, or investigate security incidents.  
**Remediation:** Add the `enabled_cluster_log_types` argument with all five log types: `["api", "audit", "authenticator", "controllerManager", "scheduler"]`.
