**Remediation Briefing: EKS Cluster Security Misconfigurations**

Below are the failing checks in the order reported by the scanner. Each entry identifies the resource, the exact lines that trigger the finding, a concise statement of the problem, and the change required to make the check pass.

---

### 1. CKV_AWS_58 on `aws_eks_cluster.disabled` (lines 3‑12)
**Trigger:** The entire resource block (lines 3‑12) contains no `encryption_config` block.  
**Problem:** The cluster does not have secrets encryption enabled; Kubernetes secrets are stored in etcd without envelope encryption.  
**Change:** Add an `encryption_config` block inside the resource, providing a `provider` block with a `key_arn` that points to a valid KMS key.

### 2. CKV_AWS_37 on `aws_eks_cluster.disabled` (lines 3‑12)
**Trigger:** The resource block (lines 3‑12) does not include the `enabled_cluster_log_types` argument.  
**Problem:** Control plane logging is not enabled for all log types, reducing auditability and visibility into cluster operations.  
**Change:** Add the argument `enabled_cluster_log_types` set to the list `["api", "audit", "authenticator", "controllerManager", "scheduler"]`.

### 3. CKV_AWS_39 on `aws_eks_cluster.restricted` (lines 14‑23)
**Trigger:** The `vpc_config` block (lines 18‑22) does not set `endpoint_public_access`; it defaults to `true`.  
**Problem:** The public endpoint is enabled, exposing the EKS control plane to the internet.  
**Change:** Inside the `vpc_config` block, set `endpoint_public_access = false`.

### 4. CKV_AWS_58 on `aws_eks_cluster.restricted` (lines 14‑23)

**Summary of required changes across all resources:**
- **Secrets encryption (CKV_AWS_58):** Add an `encryption_config` block referencing a KMS key to every cluster.
