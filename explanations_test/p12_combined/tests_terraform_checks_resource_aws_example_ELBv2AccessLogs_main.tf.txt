## Remediation Briefing

Below is a per‑finding breakdown of every failing check, the exact resource and lines that trigger it, what is wrong, why it matters, and the change required to make the check pass.  
All evidence is drawn solely from the scanner output and the provided Terraform file.

---

### 1. CKV_AWS_152 on `aws_lb.enabled` (lines 3‑12)
**What is wrong:** The Network Load Balancer does not have cross‑zone load balancing enabled.  
**Why it matters:** Without cross‑zone load balancing, traffic may not be evenly distributed across targets in different Availability Zones, which can lead to uneven load and reduced resilience.  
**Change needed:** Add the attribute `enable_cross_zone_load_balancing = true` to the `aws_lb` resource.

### 2. CKV_AWS_150 on `aws_lb.enabled` (lines 3‑12)
**What is wrong:** Deletion protection is not enabled on the load balancer.  
**Why it matters:** Without deletion protection, the load balancer can be deleted accidentally, causing an outage.  
**Change needed:** Add `enable_deletion_protection = true` to the resource.

### 3. CKV_AWS_150 on `aws_alb.enabled` (lines 14‑23)
**What is wrong:** Deletion protection is not enabled on the Application Load Balancer.  
**Why it matters:** Same risk as above – accidental deletion would disrupt all services behind this ALB.  
**Change needed:** Add `enable_deletion_protection = true` to the `aws_alb` resource.

### 4. CKV_AWS_131 on `aws_alb.enabled` (lines 14‑23)
**What is wrong:** The ALB is not configured to drop invalid HTTP headers.  
**Why it matters:** When this setting is off, the ALB forwards malformed or invalid headers to targets, which could be exploited for HTTP header injection attacks.  
**Change needed:** Add `drop_invalid_header_fields = true` to the `aws_alb` resource.
