**Remediation Briefing: CKV_AWS_275 – Disallow AWS AdministratorAccess Policy**

Below are the two failing findings, in the order they appear in the scanner output. Both relate to the same misconfiguration: referencing the AWS managed `AdministratorAccess` policy in a data source.

---

### 1. CKV_AWS_275 on `data.aws_iam_policy.fail1` (lines 3–5)

**What is wrong**  
The data source is fetching the AWS managed policy named `AdministratorAccess`.

**Why it matters**  
`AdministratorAccess` grants full administrative permissions (`*` on `*`) to any principal it is attached to. Using it – even as a data source reference for later attachment – indicates an intent to assign excessive, unrestricted privileges. This violates the principle of least privilege and significantly increases the blast radius if the associated identity is compromised.

**Remediation**  
Replace the `name` argument with the name of a more restrictive, purpose-built AWS managed policy (or a customer-managed policy) that provides only the permissions actually required. For example, if the intended use is read-only access to S3, use `AmazonS3ReadOnlyAccess` as shown in the passing example. If no suitable AWS managed policy exists, create a custom policy with the minimum necessary actions and resources, and reference that instead.

---

### 2. CKV_AWS_275 on `data.aws_iam_policy.fail2` (lines 7–9)

**What is wrong**  
The data source is fetching the AWS managed policy by its ARN, `arn:aws:iam::aws:policy/AdministratorAccess`.

**Why it matters**  
The same risk applies regardless of whether the policy is referenced by name or ARN. The ARN explicitly points to the `AdministratorAccess` policy, which provides unrestricted access. This is a direct violation of the security control that prohibits the use of this policy.

**Remediation**  
Change the `arn` argument to reference a policy that grants only the permissions needed for the workload. For instance, use `arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess` or the ARN of a custom policy you have created. Ensure the replacement policy is scoped down to the specific services, actions, and resources required.

---

**Interaction note**  
The two failing data sources are independent; fixing one does not affect the other. Both must be updated individually to reference a non-`AdministratorAccess` policy. The passing examples in the file (`pass1`, `pass2`) illustrate the correct pattern.
