**Check CKV_AWS_186 on `aws_s3_bucket_object.this_file_2` (lines 2–5)**  
**What is wrong:** The S3 object is not configured to use KMS encryption with a customer managed key (CMK).  
**Why it matters:** Without explicit KMS encryption using a CMK, the object will be encrypted at rest with S3-managed keys (SSE-S3) or the bucket’s default encryption setting, which may not meet compliance requirements. Customer managed keys give you full control over key lifecycle, access policies, rotation, and provide detailed audit trails via CloudTrail. This is often required for regulatory standards (e.g., PCI-DSS, HIPAA) and internal security policies.  
**Change needed:** Add the `server_side_encryption` argument set to `"aws:kms"` and provide a `kms_key_id` that references the ARN (or alias) of a customer managed KMS key. The key must exist in the same region as the bucket, and the principal writing the object must have `kms:GenerateDataKey` and `kms:Decrypt` permissions on that key. If the bucket already has default encryption with KMS, you may still need to set these arguments on the object to satisfy the check explicitly. No other resources in the supplied file interact with this object, so no cross-resource conflicts need to be addressed.
