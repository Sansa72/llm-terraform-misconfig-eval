**Check:** CKV_AWS_186 on `aws_s3_bucket_object.this_file_2` (lines 2-5)  
**What is wrong:** The S3 object is not configured to use server-side encryption with a customer-managed KMS key (CMK).  
**Why it matters:** Without explicit KMS encryption using a CMK, the object may be stored unencrypted or encrypted with an S3-managed key (SSE-S3), which does not give you control over key rotation, access policies, or detailed audit trails. Using a CMK ensures you retain ownership of the encryption key, can enforce least-privilege access, and meet compliance requirements that mandate customer-controlled encryption.  
**Change needed:** Add the `server_side_encryption` argument set to `"aws:kms"` and provide the ARN of a customer-managed KMS key via the `kms_key_id` argument. The key must already exist (or be referenced from a data source) and the bucket’s IAM policies must allow the principal writing the object to perform `kms:GenerateDataKey` and `kms:Decrypt` on that key. If the object requires an encryption context for additional access control, you can also specify `kms_encryption_context`. No other resources in the supplied file interact with this fix.
