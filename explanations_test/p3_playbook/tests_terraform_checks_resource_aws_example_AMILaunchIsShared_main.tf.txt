- **Check: CKV_AWS_205 – Ensure to Limit AMI launch Permissions**  
  **Resource:** `aws_ami_launch_permission.fail` (lines 1-4)  
  **What’s wrong:** The AMI launch permission is granted to a single, hard-coded AWS account ID (`987654321`) without any validation that this account is authorized.  
  **Why it matters:** Sharing an AMI with an untrusted or unintended account can allow that account to launch EC2 instances from your AMI, potentially exposing proprietary software, sensitive data baked into the image, or internal network configurations. Even a single mis‑shared AMI can lead to data leakage or unauthorized access to your environment.  
  **Remediation:** Review whether the account ID `987654321` genuinely needs access to this AMI. If it does, confirm the ID is correct and belongs to a trusted entity. If the AMI should be shared with multiple accounts, replace the hard-coded `account_id` with a variable and use `for_each` to create one `aws_ami_launch_permission` per trusted account, keeping the list of accounts in a controlled variable. If the permission is not needed, remove the resource entirely. Never use a wildcard or “all” group; always explicitly list only the accounts that require access.
