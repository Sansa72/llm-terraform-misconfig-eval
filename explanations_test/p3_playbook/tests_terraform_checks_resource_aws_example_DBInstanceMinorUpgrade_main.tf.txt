Below is a remediation briefing covering every failing check in the order presented by the scanner. Each entry names the check and resource, states the problem in one line, explains why it matters, and describes the required change in prose. Interactions between fixes are noted where the existing file makes them relevant.

---

### 1. CKV_AWS_354 on `aws_rds_cluster_instance.fail` (lines 1-7)
**What is wrong:** Performance Insights is not configured to use a customer-managed KMS key.  
**Why it matters:** Without a KMS CMK, Performance Insights data is encrypted using the default AWS-managed key, which may not meet organizational key management or compliance requirements.  
**Change needed:** Set `performance_insights_enabled = true` and provide a valid KMS key ARN in `performance_insights_kms_key_id`. This will also satisfy CKV_AWS_353 (Performance Insights enabled) for this resource.

### 2. CKV_AWS_353 on `aws_rds_cluster_instance.fail` (lines 1-7)
**What is wrong:** Performance Insights is explicitly disabled (`performance_insights_enabled = false`).  
**Why it matters:** Performance Insights provides critical database performance monitoring and tuning data. Disabling it reduces visibility into query performance and resource bottlenecks.  
**Change needed:** Set `performance_insights_enabled = true`. If you also apply the fix for CKV_AWS_354 by specifying a KMS key, this check will pass automatically.

### 3. CKV_AWS_226 on `aws_rds_cluster_instance.fail` (lines 1-7)
**What is wrong:** Automatic minor version upgrades are turned off (`auto_minor_version_upgrade = false`).  
**Why it matters:** Without automatic minor upgrades, the instance may miss important security patches and bug fixes, increasing the risk of vulnerabilities.  
**Change needed:** Set `auto_minor_version_upgrade = true`.

### 4. CKV_AWS_17 on `aws_rds_cluster_instance.fail` (lines 1-7)
**What is wrong:** The instance is publicly accessible (`publicly_accessible = true`).  
**Why it matters:** Public accessibility exposes the database directly to the internet, significantly increasing the attack surface and the risk of unauthorized access.  
**Change needed:** Set `publicly_accessible = false`. Ensure the instance is placed in a private subnet and accessed only through secure channels (e.g., VPN, bastion, or VPC peering).

### 5. CKV_AWS_118 on `aws_rds_cluster_instance.fail` (lines 1-7)
**What is wrong:** Enhanced monitoring is not enabled (the `monitoring_interval` attribute is missing or 0).  
**Why it matters:** Enhanced monitoring provides real-time OS-level metrics that are essential for troubleshooting performance issues and detecting anomalies.  
**Change needed:** Set `monitoring_interval` to a value greater than 0 (e.g., 60) and, if required, provide a monitoring IAM role ARN in `monitoring_role_arn`.

### 16. CKV_AWS_129 on `aws_db_instance.fail` (lines 36-43)
**What is wrong:** Database logs are not exported to CloudWatch.  
**Why it matters:** Exporting logs (e.g., error, general, slow query) to CloudWatch is essential for auditing, troubleshooting, and security monitoring.  
**Change needed:** Add an `enabled_cloudwatch_logs_exports` list containing the desired log types (e.g., `["postgresql"]` for Postgres). This will also satisfy CKV2_AWS_30 (Postgres query logging) for this resource.

### 17. CKV_AWS_133 on `aws_db_instance.fail` (lines 36-43)
**What is wrong:** Backup retention period is set to 0, meaning automated backups are disabled.  
**Why it matters:** Without automated backups, you cannot perform point-in-time recovery, increasing the risk of permanent data loss.  
**Change needed:** Set `backup_retention_period` to a value between 1 and 35 (e.g., 7).

**Interaction notes across fixes:**
- For all resources, enabling Performance Insights (`performance_insights_enabled = true`) is a prerequisite for encrypting it with a KMS key (CKV_AWS_354). Applying the KMS key fix automatically resolves CKV_AWS_353.
- For `aws_db_instance` resources, adding `"postgresql"` to `enabled_cloudwatch_logs_exports` satisfies both CKV_AWS_129 (log exports) and CKV2_AWS_30 (Postgres query logging).
- The `aws_rds_cluster_instance.pass` and `aws_db_instance.pass` resources already pass many checks and can serve as reference patterns, though they still have some intentional failures (e.g., public accessibility) that should not be replicated.
