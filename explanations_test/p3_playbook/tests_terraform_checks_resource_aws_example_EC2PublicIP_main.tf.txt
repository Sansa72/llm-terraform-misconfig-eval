1. **CKV_AWS_79 on aws_instance.default (lines 5-8)**  
   *What’s wrong:* IMDSv1 is enabled by default because no `metadata_options` block is present.  
   *Why it matters:* IMDSv1 is vulnerable to server-side request forgery (SSRF) attacks that can leak instance metadata, including IAM credentials.  
   *Change needed:* Add a `metadata_options` block with `http_tokens = "required"` to enforce IMDSv2 and disable IMDSv1.

2. **CKV_AWS_126 on aws_instance.default (lines 5-8)**  
   *What’s wrong:* Detailed monitoring is not enabled (defaults to basic 5-minute granularity).  
   *Why it matters:* Detailed monitoring provides 1-minute CloudWatch metrics, improving alerting accuracy and auto-scaling responsiveness.  
   *Change needed:* Set `monitoring = true` in the instance resource.

3. **CKV_AWS_135 on aws_instance.default (lines 5-8)**  
   *What’s wrong:* EBS optimization is not enabled.  
   *Why it matters:* EBS-optimized instances receive dedicated throughput for EBS volumes, reducing contention and improving storage performance consistency.  
   *Change needed:* Add `ebs_optimized = true`.

4. **CKV_AWS_8 on aws_instance.default (lines 5-8)**  
   *What’s wrong:* The root EBS volume is not encrypted.  
   *Why it matters:* Unencrypted data at rest can be exposed if physical storage is compromised. Encryption protects confidentiality.  
   *Change needed:* Add a `root_block_device` block with `encrypted = true`. If a custom KMS key is required, also specify `kms_key_id`.

**Interactions and notes:**  
- All instance-level fixes (`metadata_options`, `monitoring`, `ebs_optimized`, `root_block_device` encryption, `iam_instance_profile`) can be added to the same resource block without conflict.  
- For `for_each` resources, a single change to the resource definition resolves the check for all instances created by that loop.  
- The `CKV_AWS_88` (public IP) fixes may require changing variable defaults or logic. If a public IP is truly needed, you must document the exception and implement compensating controls, but the scanner expects `associate_public_ip_address = false`.  
- Launch templates only had `CKV_AWS_79` and `CKV_AWS_88` flagged; other checks (monitoring, EBS optimization, encryption, IAM role) were not reported for launch templates in this scan, so no changes are required there beyond what is listed.
