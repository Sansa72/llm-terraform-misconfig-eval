**CKV_AWS_39 on aws_eks_cluster.pass (lines 1-15): Ensure Amazon EKS public endpoint disabled**  
*What is wrong:* The cluster does not disable the public endpoint; it defaults to `endpoint_public_access = true`.  
*Why it matters:* A public endpoint exposes the Kubernetes API server to the internet, increasing the attack surface for unauthorised access, brute‑force attempts, and denial‑of‑service.  
*Change needed:* In the `vpc_config` block, set `endpoint_public_access = false`. To retain private access from within the VPC, also set `endpoint_private_access = true`. This completely removes the public endpoint.

**CKV_AWS_58 on aws_eks_cluster.pass (lines 1-15): Ensure EKS Cluster has Secrets Encryption Enabled**  
*What is wrong:* No `encryption_config` block is present, so Kubernetes secrets are stored unencrypted in etcd.  
*Why it matters:* Without envelope encryption using a KMS key, secrets are not protected at rest. If etcd backups or snapshots are exposed, all secrets are readable.  
*Change needed:* Add an `encryption_config` block with `resources = ["secrets"]` and a `provider` block that references a valid KMS key ARN. The cluster’s IAM role must have `kms:Encrypt` and `kms:Decrypt` permissions on that key.

**CKV_AWS_38 on aws_eks_cluster.pass (lines 1-15): Ensure Amazon EKS public endpoint not accessible to 0.0.0.0/0**  
*What is wrong:* The public endpoint, if enabled, is open to the entire internet (`public_access_cidrs` defaults to `["0.0.0.0/0"]`).  
*Why it matters:* Unrestricted access allows anyone on the internet to reach the API server, increasing the risk of exploitation and unauthorised control.  
*Change needed:* If you keep the public endpoint enabled, add `public_access_cidrs` with a restricted list (e.g., your corporate IP ranges). If you disable the public endpoint entirely (as required by CKV_AWS_39), the endpoint is not reachable, which inherently satisfies this check. However, the scanner may still expect an explicit non‑`0.0.0.0/0` value; in that case, set `public_access_cidrs = ["10.0.0.0/8"]` (or another internal range) alongside `endpoint_public_access = false`.  
*Interaction:* Disabling the public endpoint for CKV_AWS_39 also addresses CKV_AWS_38, but you may need to set `public_access_cidrs` explicitly to pass the scanner.

**CKV_AWS_37 on aws_eks_cluster.pass (lines 1-15): Ensure Amazon EKS control plane logging enabled for all log types**  
*What is wrong:* No `enabled_cluster_log_types` are specified, so control plane logs are not sent to CloudWatch.  
*Why it matters:* Logs from the API server, audit, authenticator, controller manager, and scheduler are critical for security monitoring, incident response, and compliance auditing.  
*Change needed:* Add the `enabled_cluster_log_types` argument with all five log types: `["api", "audit", "authenticator", "controllerManager", "scheduler"]`.
