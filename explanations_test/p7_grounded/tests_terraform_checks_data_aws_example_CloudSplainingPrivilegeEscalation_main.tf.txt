### Resource: `data.aws_iam_policy_document.pass` (lines 3–17)

**Check CKV_AWS_111 – “Ensure IAM policies does not allow write access without constraints”**  
- **Triggered by:** The `actions` list on lines 8–10 includes `lambda:CreateFunction`, `lambda:CreateEventSourceMapping`, and `dynamodb:CreateTable`. These are write-level actions (they create resources).  
- **Why it’s flagged:** The `resources` field on line 12 is set to `"*"`, meaning the write actions are allowed on **all** resources without any constraint (e.g., a specific Lambda function ARN or DynamoDB table ARN). The check requires that write permissions be scoped to specific resources.

**Check CKV_AWS_356 – “Ensure no IAM policies documents allow ‘*’ as a statement's resource for restrictable actions”**  
- **Triggered by:** The same statement (lines 6–14) uses `resources = ["*"]` (line 12).  
- **Why it’s flagged:** The actions in this statement (`lambda:CreateFunction`, `lambda:CreateEventSourceMapping`, `dynamodb:CreateTable`) are “restrictable” – they can be limited to specific resources. Using a wildcard `"*"` as the resource for such actions violates this check.

- **Triggered by:** The action `iam:PassRole` on line 27.  
- **Why:** `iam:PassRole` is a permissions management action. The policy allows it on `"*"` (line 34), meaning it can be used to pass any role to any service. The check flags this because it grants broad ability to manage permissions without resource constraints.

**Check CKV_AWS_110 – “Ensure IAM policies does not allow privilege escalation”**  
- **Triggered by:** The combination of `iam:PassRole` with `resources = ["*"]` (lines 27 and 34).  
- **Why:** `iam:PassRole` with a wildcard resource is a well-known privilege escalation vector. It allows an identity to pass any existing role to a service (e.g., Lambda), potentially gaining the permissions of that role. The check identifies this as a direct privilege escalation risk.
