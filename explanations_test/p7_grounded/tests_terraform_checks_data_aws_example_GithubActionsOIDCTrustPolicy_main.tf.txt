### 1. CKV_AWS_111 on `aws_iam_policy_document.pass1` (lines 25–39)

**What the check says:**  
“Ensure IAM policies does not allow write access without constraints”

**Where it’s triggered:**  
Lines 25–39 define a policy document named `pass1`:

```terraform
data "aws_iam_policy_document" "pass1" {
  version = "2012-10-17"

  statement {
    effect = "Allow"
    actions = [
      "lambda:CreateFunction",
      "lambda:CreateEventSourceMapping",
      "dynamodb:CreateTable",
    ]
    resources = [
      "*",
    ]
  }
}
```

**Why it’s flagged:**  
The statement grants `Allow` for three write actions (`CreateFunction`, `CreateEventSourceMapping`, `CreateTable`) on **all resources** (`"*"`). There is no `condition` block to restrict when or by whom these actions can be used. The check interprets this as write access without constraints. Even though the resource is named `pass1`, the policy itself is overly permissive.

### 2. CKV_AWS_356 on `aws_iam_policy_document.pass1` (lines 25–39)

**What the check says:**  
“Ensure no IAM policies documents allow "*" as a statement's resource for restrictable actions”

**Where it’s triggered:**  
Same resource, same lines (25–39). The `resources` field is set to `["*"]`.

**Why it’s flagged:**

The check requires that restrictable actions are not paired with a wildcard resource.

The check requires a condition that ties the trust to a specific known organization.
