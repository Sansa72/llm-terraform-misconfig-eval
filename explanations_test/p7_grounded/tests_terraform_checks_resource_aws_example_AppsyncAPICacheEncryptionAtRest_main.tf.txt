The scanner flagged two separate issues on the `aws_appsync_api_cache` resources named `fail` and `fail2`:

1. **CKV_AWS_215** – “Ensure Appsync API Cache is encrypted in transit”
2. **CKV_AWS_214** – “Ensure Appsync API Cache is encrypted at rest”

Both checks were raised against the same two resources, so I’ll address them together.

---

### What the checks require
- **CKV_AWS_215** expects the argument `transit_encryption_enabled` to be set to `true`.
- **CKV_AWS_214** expects the argument `at_rest_encryption_enabled` to be set to `true`.

The resource `aws_appsync_api_cache.pass` (lines 1–9) shows the compliant pattern: both arguments are explicitly `true`.

---

### Resource `aws_appsync_api_cache.fail` (lines 10–17)
```terraform
resource "aws_appsync_api_cache" "fail" {
  api_id                     = aws_appsync_graphql_api.default.id
  transit_encryption_enabled = false          # <-- line 13
  at_rest_encryption_enabled = false          # <-- line 14
  ttl                        = 60
  type                       = "SMALL"
  api_caching_behavior       = "FULL_REQUEST_CACHING"
}
```
- **Line 13** sets `transit_encryption_enabled = false`. This directly violates CKV_AWS_215.
- **Line 14** sets `at_rest_encryption_enabled = false`. This directly violates CKV_AWS_214.

The fix is to change both values to `true`, matching the `pass` resource.

---

### Resource `aws_appsync_api_cache.fail2` (lines 19–24)
```terraform
resource "aws_appsync_api_cache" "fail2" {
  api_id               = aws_appsync_graphql_api.default.id
  ttl                  = 60
  type                 = "SMALL"
  api_caching_behavior = "FULL_REQUEST_CACHING"
}
```
- The arguments `transit_encryption_enabled` and `at_rest_encryption_enabled` are **completely absent**.  
  The scanner treats the absence as non‑compliant for both CKV_AWS_215 and CKV_AWS_214.  
  (In Terraform, omitting an optional boolean typically results in the provider’s default, which for these attributes is `false`.)

The fix is to add both arguments and set them to `true`:
```terraform
transit_encryption_enabled = true
at_rest_encryption_enabled = true
```

---

### Summary
- **CKV_AWS_215** (transit encryption) and **CKV_AWS_214** (at‑rest encryption) are failing on both `fail` and `fail2` because the attributes are either explicitly `false` or missing.
- The `pass` resource demonstrates the required configuration: both arguments set to `true`.
- No other resources or attack scenarios are evidenced in the provided file; the finding is based solely on the attribute values shown.
