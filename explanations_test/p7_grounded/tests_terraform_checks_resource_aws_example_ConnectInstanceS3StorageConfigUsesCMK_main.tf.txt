### Finding 2: CKV_AWS_270 on `aws_connect_instance_storage_config.fail` (lines 19-34)

**Check description:** Ensure Connect Instance S3 Storage Config uses CMK.

**What the file shows:**  
The `fail` resource defines an S3 storage config with an `encryption_config` block (lines 28-30):

```terraform
encryption_config {
  encryption_type = "KMS"
}
```

A `key_id` is **not** specified.

**Problem:**  
The encryption type is set to `"KMS"`, but no customer-managed key (CMK) is provided via `key_id`. When `key_id` is omitted, Amazon Connect uses an AWS-managed KMS key, not a customer-managed CMK. The check requires a CMK. The fix is to add a `key_id` attribute referencing a customer-managed KMS key ARN, similar to the `pass` resource (line 12: `key_id = aws_kms_key.example.arn`).
