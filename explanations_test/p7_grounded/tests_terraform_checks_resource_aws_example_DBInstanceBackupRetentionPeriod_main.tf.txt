### `aws_rds_cluster.pass` (lines 1–3)
**File content:**
```terraform
resource "aws_rds_cluster" "pass" {
  backup_retention_period = 35
}
```
**Findings:**
- CKV_AWS_313 – copy tags to snapshots
- CKV_AWS_96  – encryption at rest
- CKV_AWS_162 – IAM authentication
- CKV_AWS_326 – backtracking
- CKV_AWS_327 – KMS CMK encryption
- CKV_AWS_325 – audit logging (MySQL)
- CKV_AWS_139 – deletion protection
- CKV_AWS_324 – log capture
- CKV2_AWS_8  – AWS Backup plan

**Why they fire:**  
The resource block contains **only** `backup_retention_period`. All the checks above look for specific attributes that are absent. For example:
- `copy_tags_to_snapshot` is not set → CKV_AWS_313 fails.
- `storage_encrypted` is not set → CKV_AWS_96 fails.
- `iam_database_authentication_enabled` is not set → CKV_AWS_162 fails.
- `backtrack_window` is not set (Aurora‑specific) → CKV_AWS_326 fails.
- `kms_key_id` is not set → CKV_AWS_327 fails.
- `enabled_cloudwatch_logs_exports` is not set → CKV_AWS_325, CKV_AWS_324 fail.
- `deletion_protection` is not set → CKV_AWS_139 fails.
- No AWS Backup plan is associated in the given code → CKV2_AWS_8 fails.

**Note:** `backup_retention_period = 35` is valid, so CKV_AWS_133 (backup policy) is **not** raised here.

### What the engineer must do
For every resource, add the missing attributes to satisfy the checks. The exact values depend on your security policy, but the attributes that must be present are:

**For `aws_rds_cluster`:**
- `copy_tags_to_snapshot = true`
- `storage_encrypted = true`
- `iam_database_authentication_enabled = true`
- `backtrack_window = <seconds>` (Aurora only)
- `kms_key_id = <arn>` (or set to a KMS key)
- `enabled_cloudwatch_logs_exports = ["audit", "error", ...]`
- `deletion_protection = true`
- Associate the cluster with an AWS Backup plan (or define one in Terraform).

**For `aws_db_instance`:**
- `copy_tags_to_snapshot = true`
- `storage_encrypted = true`
- `deletion_protection = true`
- `performance_insights_enabled = true`
- `performance_insights_kms_key_id = <arn>`
- `multi_az = true`
- `enabled_cloudwatch_logs_exports = ["audit", "error", ...]`
- `auto_minor_version_upgrade = true`
- `monitoring_interval = <non‑zero>` and `monitoring_role_arn`

**Fix invalid backup retention:**
- `fail` resources: change `backup_retention_period` to a value between 1 and 35.
- `fail2` resources: set a positive retention period (e.g., 7) to enable backups.

The resource named `unknown` uses a variable; ensure that variable’s value is valid and add all the missing security attributes.

All findings are grounded in the absence of these attributes in the provided file. No other assumptions are needed.
