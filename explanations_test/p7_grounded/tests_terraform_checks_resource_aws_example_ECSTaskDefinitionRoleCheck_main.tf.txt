### 1. CKV_AWS_336 – Containers lack read-only root filesystem

**Resources affected:**  
- `aws_ecs_task_definition.pass` (lines 1–20)  
- `aws_ecs_task_definition.fail` (lines 22–41)

**What the check requires:**  
ECS containers should have the `readonlyRootFilesystem` attribute set to `true` in their container definition. This limits the container’s root filesystem to read-only access, reducing the risk of malicious or accidental writes.

**Evidence in the file:**  
Both task definitions define their container configurations via `jsonencode` (lines 3–17 and 24–38). In both cases, the JSON object includes `name`, `image`, `cpu`, `memory`, `essential`, and `portMappings`, but **no `readonlyRootFilesystem` property**. Because the default value is `false`, the scanner correctly flags both resources.

**What to fix:**  
Add `"readonlyRootFilesystem": true` to the container definition JSON in both resources. For example, in the `pass` resource (line 3), the JSON would become:

```json
{
  "name": "first",
  "image": "service-first",
  "cpu": 10,
  "memory": 512,
  "essential": true,
  "readonlyRootFilesystem": true,
  "portMappings": [
    {
      "containerPort": 80,
      "hostPort": 80
    }
  ]
}
```

Apply the same change to the `fail` resource.

### 2. CKV_AWS_249 – Execution role and task role are identical

**Resource affected:** `aws_ecs_task_definition.fail` (lines 22–41)

**What the check requires:**  
The ECS task execution role (used by the ECS agent to pull images, write logs, etc.) and the task role (used by the container itself) must be different IAM roles. This enforces least privilege by preventing the container from having the same permissions as the ECS agent.

**Evidence in the file:**  
Lines 39–40 show:

```terraform
execution_role_arn = "aws_iam_role.example.arn"
task_role_arn      = "aws_iam_role.example.arn"
```

Both attributes reference the same IAM role ARN. The scanner therefore flags this resource.

**What to fix:**  
Assign distinct IAM roles. For example, keep the execution role as `aws_iam_role.example.arn` and change the task role to a different role, such as `aws_iam_role.task.arn`. The `pass` resource (lines 19–20) already demonstrates this separation correctly.

---

**Summary of actions:**
- Add `"readonlyRootFilesystem": true` to the container definition JSON in both task definitions.
- Change the `task_role_arn` in the `fail` resource to a different IAM role than the execution role.
