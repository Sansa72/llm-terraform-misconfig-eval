The scanner flagged four findings across your `aws_elb` resources. Here’s what each one means, backed strictly by the file and the check descriptions.

### 1. `CKV_AWS_127` on `aws_elb.fail` (lines 2–34)
**Check:** *Ensure that Elastic Load Balancer(s) uses SSL certificates provided by AWS Certificate Manager*

**Trigger:** The resource defines an HTTPS listener at **lines 13–19**:
```terraform
listener {
    instance_port      = 8000
    instance_protocol  = "http"
    lb_port            = 443
    lb_protocol        = "https"
    ssl_certificate_id = "foo"
}
```
The `ssl_certificate_id` is set to the literal string `"foo"`. This is not a valid Amazon Resource Name (ARN) for a certificate issued by AWS Certificate Manager (ACM). The check expects any HTTPS listener to reference an ACM certificate. Because the value is a placeholder, the resource fails this control.

### 2. `CKV_AWS_92` on `aws_elb.fail` (lines 2–34)

**Trigger:** The entire resource block (lines 2–34) contains **no `access_logs` block**. Access logging is not configured anywhere in this ELB definition. The check requires an `access_logs` sub-block (with an S3 bucket and optional prefix) to enable logging of requests sent to the load balancer.
